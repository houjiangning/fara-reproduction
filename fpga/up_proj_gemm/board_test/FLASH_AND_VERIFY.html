A生成含 GEMM 的新比特流

A1　把 GEMM 接进 Block Design

Vivado 现在正开着 up_proj_gemm.xpr（GUI 模式），不要再开一个 batch 实例抢工程。直接在当前 Vivado 的 Tcl Console 里执行：

source C:/Users/houji/Desktop/doc/study/llm-fpga-security-literature/fara-reproduction/fpga/up_proj_gemm/tools/add_gemm_to_bd.tcl

脚本 tools/add_gemm_to_bd.tcl 已改成两用：GUI 里 source 会复用已打开的工程且不关闭它；vivado -mode batch 下会自动开/关工程。它依次完成：

  1. 生成 fp32_mul_ip（C_Latency=8）与 fp32_add_ip（C_Latency=4），并校验 IP 延迟 == RTL 参数，不一致直接报错退出（防止流水线错位）。
  2. 把 6 个 RTL 文件加入 sources_1：gemm_up_proj_core.sv / gemm_up_proj_axi_lite.sv / gemm_up_proj_top.sv / gemm_up_proj_bd.v / fp32_mul.sv / fp32_add.sv。
  3. 删除 axis_data_fifo_0（旧自环）。
  4. 新建 gemm_up_proj_bd_0（用 Verilog shim，因为 Vivado 2022.2 不允许 BD 直接引用 SystemVerilog 顶层模块）。
  5. 连线：
    • axi_dma_0/M_AXIS_MM2S → gemm_up_proj_bd_0/s_axis
    • gemm_up_proj_bd_0/m_axis → axi_dma_0/S_AXIS_S2MM
    • smartconnect_0/M01_AXI → gemm_up_proj_bd_0/s_axi（smartconnect_0 NUM_MI 由 1 改为 2）
    • pl_clk0 → s_axi_aclk；peripheral_aresetn → s_axi_aresetn
    • 顺带补上原本悬空的 smartconnect_1/aresetn
  6. 地址分配 0xA0010000 / 64K。
  7. validate_bd_design + save_bd_design。
成功标志 Tcl Console 最后应打印 == ADD_GEMM_DONE，并且能看到 == FP_IP_LATENCY mul=8 (want 8)  add=4 (want 4) 和 == MAP ... offset=0x00A0010000 range=64K。
不想用 Tcl 也可以手工做 ① 选中 axis_data_fifo_0 按 Delete；② 右键空白处 → Add Module… 选 gemm_up_proj_bd；③ 按上面 5 条连线；④ 打开 Address Editor 给 gemm_up_proj_bd_0/S_AXI 填 0xA0010000 / 64K；⑤ 按 F6 或点 Validate Design。

Address Editor 里 gemm_up_proj_bd_0/S_AXI 应为 0xA0010000、64K，且没有黄色未分配段（Unmapped）。

A3　重新生成比特流

GUI：在 Sources 面板右键 up_proj_wrapper → Generate Bitstream（弹出提示一律选 Yes / Save）。

或 Tcl：

reset_run synth_1
launch_runs synth_1 -jobs 8
wait_on_run synth_1
launch_runs impl_1 -to_step write_bitstream -jobs 8
wait_on_run impl_1
三个必须注意的点
  • 新增了 fp32_mul_ip / fp32_add_ip 两个 OOC IP，会多出各自的 synth/impl run；synth_1 必须整条重跑，不能只重跑 impl。
  • 判定完成：get_property STATUS [get_runs impl_1] 必须等于 write_bitstream Complete!。之前踩过的坑就是所有 run 停在 Scripts Generated / PROGRESS 0%（Windows 计算机名含非 ASCII 字符导致 Tcl 崩溃），计算机名已改为纯英文，应不再复现。
  • 产物时间戳必须是今天：up_proj_gemm.runs/impl_1/up_proj_wrapper.bit。

A4　转成 fpga_manager 能吃的 .bit.bin

up_proj_gemm.runs/impl_1/up_proj.bif 已存在且内容正确：

all:
{
    [destination_device = pl] up_proj_wrapper.bit
}

在该目录下执行（bootgen 位于 D:\Download\Xilinx_Vivado\Vivado\2022.2\bin\）：

# 在 up_proj_gemm.runs/impl_1 目录下执行
bootgen -image up_proj.bif -arch zynqmp -o up_proj_wrapper.bit.bin -w

产物 up_proj_wrapper.bit.bin 约 19.3 MB（比 .bit 略大，因为文件头被换成了 ZynqMP boot header）。

两种格式不能互换 Vivado Hardware Manager（JTAG 下载）吃 .bit；Linux fpga_manager 吃 .bit.bin。直接把 .bit 改名成 .bit.bin 是最常见的翻车原因——必须用 bootgen 转换。

B烧录到板卡

B0　硬件连接

连接位置用途 / 备注

启动模式拨码 SW6 = 1000（1=ON，2=OFF，3=OFF，4=OFF）为 SD 启动；0000 为 JTAG 启动。

最容易忽略的一条 ZynqMP 上 PL 的比特流里不包含 PS 配置。下面三样由 BOOT.BIN 里的 FSBL / psu_init 决定，跟 bitstream 无关：
  1. pl_clk0 是否使能 —— 本设计全部逻辑都靠它，没有时钟 PL 就是死的
  2. M_AXI_HPM0_FPD 是否使能 —— PS 读写 PL 寄存器（0xA0000000 / 0xA0010000）的通路
  3. S_AXI_HP0_FPD 是否使能 —— DMA 访问 DDR 的通路
Xilinx 官方 ZCU106 Ubuntu 镜像的 BOOT.BIN 通常已使能这三项，所以下面 B2 一般能直接跑通。若 dma_probe 读出全 0 或整机挂死，根因就是这里 → 用你的 XSA 重建 BOOT.BIN。

B1　推荐先做路径一：JTAG 直接烧 PL

最快证明「PL 设计本身没问题」，绕开 SD / BOOT.BIN / Linux。

步骤
  1. 板卡上电，确认 Vivado Hardware Server 已在运行（GUI 打开即已运行）。
  2. Vivado 左下 Open Hardware Manager → Open Target → Auto Connect。左侧应出现 xczu7ev_0。
  3. 右键 xczu7ev_0 → Program Device。
  4. Bitstream 选 up_proj_gemm.runs/impl_1/up_proj_wrapper.bit（注意是今天新生成的那个），点 Program。
  5. 进度条走完、日志出现 End of startup status: HIGH，板上 DONE 指示灯亮。
这条路径的定位 它只把 PL 配置进去，不动 PS。所以你可以：先用 SD 启动 Ubuntu（让 BOOT.BIN 把 PS 配好、PL 时钟开起来），再用 JTAG 把新 bitstream 覆盖进 PL，然后回到串口跑验证程序 —— 这是 bring-up 阶段最省事的组合。

B2　目标流程路径二：SD 启动 Ubuntu + fpga_manager 运行时加载

系统起来后，在串口 / SSH 里执行：

# 1) 确认驱动与节点存在
ls /sys/class/fpga_manager/
cat /sys/class/fpga_manager/fpga0/state        # 加载前通常为 unknown

# 2) 放进 /lib/firmware
sudo mkdir -p /lib/firmware
sudo cp /media/usb/up_proj_wrapper.bit.bin /lib/firmware/
sync

# 3) 选 full bitstream（flags=0 = 全量配置；置位则是 partial / DPR）
echo 0 | sudo tee /sys/class/fpga_manager/fpga0/flags

# 4) 触发加载
echo up_proj_wrapper.bit.bin | sudo tee /sys/class/fpga_manager/fpga0/firmware

# 5) 判定
cat /sys/class/fpga_manager/fpga0/state        # 期望：operating
dmesg | tail -20                               # 期望：fpga_manager ... operating

state 变成 operating 就表示 PL 已配置完成。

B3　可选 · 长期方案路径三：BOOT.BIN 内嵌 bitstream

把 bitstream 编进 BOOT.BIN，FSBL 上电即配置 PL，不用每次手动加载。需要 FSBL / PMUFW / ATF / U-Boot 全部与你的 XSA 匹配，属于重建启动镜像，风险和工量都大。验证阶段先不做，等 GEMM 打通、进入 W4 端到端阶段再考虑。

C验证方法（逐层，失败即停）

按 L0 → L4 顺序做，每一层失败就先修这一层，不要跳。

L0　比特流是否真的进了 PL

cat /sys/class/fpga_manager/fpga0/state    # operating
dmesg | grep -i fpga

判据：operating。
失败：state 不是 operating → 看 dmesg；最常见原因是把 .bit 直接改名成 .bit.bin（没走 bootgen）。

L1　AXI-Lite 控制通路（dma_probe）

cd /home/ubuntu/board_test
gcc -O2 -o dma_probe dma_probe.c
sudo ./dma_probe

判据：

  • 复位后 MM2S_DMASR：Halted=1 Idle=1
  • 写 MM2S_DMACR.RS=1 后 Halted 变为 0
  • 脚本打印 >>> 通过：AXI-Lite 控制通路可用。

这一步同时证明三件事：bitstream 已生效、pl_clk0 在跑、M_AXI_HPM0_FPD 已使能。（脚本里的基址 0xA0000000 与 BD 中 axi_dma_0/S_AXI_LITE 一致。）

L2　GEMM 自己的寄存器读写

仿照 dma_probe.c 写一个 20 行的小程序，mmap 0xA0010000：

VERSION  (0x18)  读 → 应等于 RTL 里写死的版本号
K_COLS   (0x0C)  写 768  → 读回 768
N_TOKENS (0x10)  写 4    → 读回 4
STATUS   (0x04)  读 → busy=0

判据：读回值与写入值一致。这一步单独验证 GEMM 的 AXI-Lite 从机已经活了 —— 把「GEMM 没接上」和「DMA 没通」两类故障分开定位。

L3　DMA 数据通路 + GEMM 功能 bit-exact

这是核心验证。需要一块物理连续的 DMA 缓冲区，推荐两条路：

方案说明
dma-proxy（Xilinx 官方） 提供 /dev/dma_proxy_tx / /dev/dma_proxy_rx，用户态 mmap 缓冲区即可。需要编译内核模块：sudo apt install build-essential linux-headers-$(uname -r)，并按你的内核调整 dma-proxy.h 与设备树节点。
udmabuf（更轻） 加载 udmabuf.ko 后得到 /dev/udmabuf0，已知物理地址，用户态 mmap 后用 /dev/mem 直接写 DMA 寄存器（复用 dma_probe 的套路），不用写内核模块。

用户态测试程序的流程：

  1. 分配 tx / rx 缓冲（4 KB 对齐）。
  2. 按 RTL 约定把 [X | b | W] 排成 64-bit AXI-Stream 流（注意 tlast 边界）。
  3. 写 K_COLS / N_TOKENS / M_ROWS，写 CTRL 启动。
  4. MM2S 发数据 → GEMM 运算 → S2MM 收结果。
  5. 与 tools/gen_golden_vectors.py 生成的 golden 逐 bit 比对。
判据 与 golden 逐位一致（bit-exact）；若最终采用放宽误差界的方案，则误差必须落在事先书面约定的界内。测试权重可用 board_export/board_W_transformer_h_0_mlp_c_fc.bin（9,437,184 B）与 board_b_*.bin（12,288 B）。

L4　端到端

PC ↔ PS ↔ PL 全链路：PC 下发激活 → PS 转发 → PL 算 GEMM → 回传 → 与 torch h.0.mlp.c_fc 的结果比对。这一层属于 W2/W4 的通路联调，等 L3 过了再做。
