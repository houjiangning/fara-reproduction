1 · 步骤 2：集成 FaR RTL 并重编译 bitstream

为什么不用重新打包 IP： BD 里 GEMM 是以 module reference （create_bd_cell -type module -reference gemm_up_proj_bd）方式例化的， rtl/*.sv 就是普通工程源文件。改 RTL 不需要重打包 IP，只要把新文件 注册进工程、再把 synth/impl 重跑一遍即可。

1.1 改动清单（已完成，仅供核对）

文件关键改动
rtl/far_reroute.sv 新模块。读 xbuf 的 X 激活 → 按 FaRMap 把敏感列 A 的激活 ×(1/div) 写到本列、并把同值加到 dead 列 → 写回 xbuf。含 clr 同步清零、st_phase 诊断输出。
rtl/gemm_up_proj_core.sv 状态机新增 S_REWIRE = 4'd9：S_LOAD_X 收完最后一拍 → S_REWIRE → far_done → S_LOAD_B。xbuf 读写口在 S_REWIRE 期间交给 u_far。
rtl/gemm_up_proj_axi_lite.sv 新增 FaRMap 间接寻址寄存器组 0x30~0x54，VERSION 改为 0x0002_0000。
rtl/gemm_up_proj_top.sv FaR 连线从 axi_lite 透传到 core，const_version = 32'h0002_0000。
tools/add_gemm_to_bd.tcl RTL 文件表加入 far_reroute.sv（缺了会在综合时报 module not found）。

3 · 步骤 4：板上 L2 / L3 / L4 验证

第一原则：运行期绝不对 SD 卡 ext4 rootfs 写一个字节。
上次卡死的直接原因是 rootfs 的 ext4 日志区写失败 （ext4_journal_check_start: Detected aborted journal），内核把文件系统整体置只读 → 系统死。 因此所有工作目录、编译产物、日志一律落在 /dev/shm（tmpfs，内存）下。 不要 cd 到 ~ 或其它 rootfs 目录编译运行。

    time min=x.xxx ms  avg=x.xxx ms
    mismatches vs Y_far:    0 / 3072   OK
    FAR_HITS  = 16 (expect 16)   OK
    FAR_PHASE = 0 (expect 0)     OK
[7] summary
    hardware baseline vs sw Y_shadow : BIT-EXACT
    hardware FaR      vs sw Y_far    : BIT-EXACT
    FAR_HITS/PHASE diagnostics       : OK
    hw FaR extra time (min)          : x.x us  (x.xx% of run)
    conservation |Y_far-Y_base| max  : x.xxxe-xx  (rel x.xxxe-xx)
>>> L4 PASS: hardware FaR == software FaR (bit-exact), and it costs ~0 extra time.
这三行就是整个 FaR 硬件化的结论：
  1. BIT-EXACT：硬件 FaR 输出 = 软件 FaR golden（逐 bit），硬件忠实复刻软件语义；
  2. BIT-EXACT：far_en=0 时输出 = shadow golden，即关掉 FaR 就是普通 GEMM；
  3. extra time ≈ 0：FaR 的额外代价被吃进数据通路（S_REWIRE 一相），不占 CPU、不增加墙钟时间—— 这正是「硬件防护优于软件防护」的直接证据。

0x38FAR_IDXRW[3:0] 当前条目下标
0x3CFAR_ARW[15:0] 敏感输入通道 A
0x40FAR_INVRWfp32 1/div（div=2 → 0x3F000000）
0x44FAR_NDRW[1:0] dead lane 条数（1..2）
0x48FAR_D0RW[15:0] dead 通道 #0
0x4CFAR_D1RW[15:0] dead 通道 #1
0x50FAR_HITSR本次重路由实际改写元素数（= N·Σ(1+nd)）
0x54FAR_PHASERfar_reroute 相位码（空闲 = 0）
其它未映射R返回 0xDEADBEEF

A.4 排障对照表

现象原因处理
L2: VERSION = 0x00010000 FAIL板卡里还是旧 bitstream回步骤 2 重编译，重烧 .bit.bin
L2: 未映射偏移不是 0xDEADBEEF地址译码 / BD 地址段错查 Address Editor：GEMM S_AXI = 0xA0010000 / 64K
L3: 输出全 0xA5A5A5A5，err=1in_cnt != in_total 或末拍无 tlast检查 in_tlast_seen 单驱动逻辑
L3: 数值不一致但 err=0累加顺序契约不符确认 G=8 / ADD_LAT=4 / MUL_LAT=8 与 RTL 一致；向量来自同一 gen_golden_vectors.py
L4: FAR_HITS 不符FaRMap 条目数/nd 与 golden 不一致确认用的是同一份 .fmap；期望值 = N·Σ(1+nd)
L4: FAR_PHASE != 0重路由未跑完（事务结束后相位没回 R_IDLE）多为 cfg_soft_rst 未接 far_reroute.clr，或时序不匹配
dma_heap alloc 失败无 /dev/dma_heap/reserved检查内核命令行 cma=；ls /dev/dma_heap/
open /dev/mem 失败没用 rootsudo ./xxx
板卡跑着跑着卡死写了 SD 卡 rootfs（ext4 日志 abort）所有操作限定在 /dev/shm；查 dmesg | grep -iE "ext4|mmcblk"
scp 报 Could not resolve hostname目标写了占位符/中文用真实 IP：ubuntu@192.168.1.200
curl: URL using bad/illegal formatURL 变量周围有空格写 http://$PC:8000/，不要 http:// $PC :8000/
